# 고해 반응 기능 User Stories

## 구성 방식

- **접근 방식**: 승인된 Hybrid 방식.
- **핵심 여정**: 반응 확인, 선택 및 해제, 재방문 시 상태 복원을
  사용자 행동 흐름으로 분리한다.
- **공통 품질 경험**: 오류, 처리 중 피드백, 접근성과 표시 일관성을
  모든 반응 접점에 적용되는 story로 정의한다.

## US-01 반응을 발견하고 의미를 이해한다

**Persona**: P-01 조용히 위로를 전하는 익명 독자, P-02 반응을 확인하는
고해 작성자

**Story**: 익명 사용자로서, 목록과 상세에서 각 고해가 받은 기도,
토닥임, 동행 반응 수를 확인하고 싶다. 그래야 표현을 남길지 판단하거나
받은 위로의 신호를 이해할 수 있다.

### Acceptance Criteria

- 목록 카드와 상세 화면에 `기도해요`, `토닥여요`, `함께해요` 세
  반응 버튼이 항상 표시된다.
- 각 버튼은 해당 반응의 현재 count를 함께 표시한다.
- backend 응답에 어떤 반응 타입이 누락되어도 해당 반응은 count `0`으로
  표시되고 선택되지 않은 상태로 보인다.
- 목록에서 반응 버튼을 조작하는 행위는 의도치 않은 상세 화면 이동을
  발생시키지 않는다.

### INVEST 점검

- **I/N/V/E/S/T**: 기존 고해 읽기 흐름 안에서 독립적으로 확인 가능하며,
  표시 기준과 누락 처리 조건이 명시되어 작게 구현하고 검증할 수 있다.

## US-02 마음에 맞는 반응을 선택하고 해제한다

**Persona**: P-01 조용히 위로를 전하는 익명 독자

**Story**: 익명 독자로서, 한 고해에 기도, 토닥임, 동행 반응을 필요에
맞게 선택하거나 취소하고 싶다. 그래야 내 마음을 부담 없이 정확하게
전할 수 있다.

### Acceptance Criteria

- 선택되지 않은 반응을 누르면 현재 device의 해당 반응이 선택된다.
- 이미 선택된 반응을 다시 누르면 현재 device의 해당 반응이 해제된다.
- 동일 고해에 대해 두 개 이상의 반응 타입을 함께 선택할 수 있으며,
  한 타입의 선택 또는 해제가 다른 타입을 자동으로 변경하지 않는다.
- 선택 또는 해제가 성공하면 서버 데이터에 따른 count와 선택 표시가
  화면에 반영된다.

### INVEST 점검

- **I/N/V/E/S/T**: 반응 조작 가치가 분명하고 타입별 결과가 관찰
  가능하므로 독립적인 사용자 행동 단위로 검증할 수 있다.

## US-03 내 선택 상태를 다시 방문해도 신뢰한다

**Persona**: P-01 조용히 위로를 전하는 익명 독자

**Story**: 익명 독자로서, 목록과 상세를 오가거나 데이터를 다시 불러온
뒤에도 내가 선택한 반응이 정확히 표시되기를 원한다. 그래야 반응을
중복으로 남기거나 실수로 취소하지 않는다.

### Acceptance Criteria

- 현재 device의 반응 선택 표시는 서버 조회 응답의
  `reactions[].selectedByMe`를 기준으로 결정된다.
- 목록 및 상세 화면은 동일 device에 대해 같은 서버 선택 상태를
  일관되게 표시한다.
- 서버 응답이 선택되지 않은 상태를 반환하면 브라우저의 과거 임시
  기록만으로 선택된 것처럼 남아 있지 않는다.
- `selectedByMe: true`인 반응은 시각적 표시와 접근 가능한 선택
  상태로 식별할 수 있다.

### INVEST 점검

- **I/N/V/E/S/T**: 상태 복원이라는 단일 사용자 문제를 대상으로 하고
  서버 기준 결과가 명시되어 수용 여부를 판별할 수 있다.

## US-04 안전하고 이해 가능한 반응 경험을 가진다

**Persona**: P-01 조용히 위로를 전하는 익명 독자, P-02 반응을 확인하는
고해 작성자

**Story**: 익명 사용자로서, 반응을 조작하거나 확인할 때 처리 상태와
실패 결과를 이해할 수 있기를 원한다. 그래야 화면의 count와 내 표현을
신뢰할 수 있다.

### Acceptance Criteria

- 반응 변경 요청 처리 중에는 반복 클릭으로 같은 영역에서 중복 조작이
  발생하지 않는다.
- 요청 실패 시 사용자는 이해 가능한 한국어 오류 메시지를 인지할 수
  있고, 성공하지 않은 count 또는 선택 상태가 남지 않는다.
- 선택된 버튼 상태는 시각적 강조만이 아니라 보조 기술에서도 인지할
  수 있도록 제공된다.
- 세 반응 버튼과 오류 경험은 목록과 상세 화면에서 일관된다.
- 사용자에게 표시되는 실패 정보는 내부 오류 상세나 device 식별
  정보를 노출하지 않는다.

### INVEST 점검

- **I/N/V/E/S/T**: 공통 품질 경험을 하나의 횡단 사용자 가치로 묶으며,
  성공 및 실패 상태가 관찰 가능해 검증 가능하다.

## Extension Alignment

- **Security Baseline Full**: US-04는 사용자 오류 표시에 민감 정보가
  드러나지 않아야 함을 수용 기준으로 포함한다. backend 검증,
  rate limiting, CORS 및 배포 보안 검증은 후속 설계와 검증 단계에서
  이어서 추적한다.
- **Property-Based Testing Partial**: US-01과 US-03의 누락 타입 처리 및
  서버 선택 상태 보존은 후속 테스트 계획에서 반응 정규화 불변식으로
  구체화할 수 있다.
